סקירת האתגר (Challenge Overview)
חדר ה-Checkmate מתמקד בהערכת נהלי סיסמאות חלשות בתוך סביבה ארגונית מדומה. מרקו ביאנקי (Marco Bianchi), מנהל מערכות, פרס לאחרונה מספר שירותים פנימיים, כולל ממשק ניהול חומת אש, פורטל עובדים, פלטפורמה חברתית וגישת SSH לתשתיות קריטיות. עקב הרגלי אבטחת סיסמאות לקויים ולחץ תפעולי, מרקו השתמש מחדש בסיסמאות חלשות, צפויות ומבוססות תבנית על פני מערכות שונות.

האתגר מדגים כיצד תוקפים יכולים להשתלט בהדרגה על שירותים באמצעות ניצול פרטי ברירת מחדל, מודיעין ממקורות גלויים (OSINT), מילונים מותאמים אישית (Custom Wordlists), פרופילינג של סיסמאות, פיצוח גיבובים (Hash Cracking) ותבניות יצירת סיסמאות צפויות. במקום להסתמך על פגיעויות תוכנה או אקספלויטים מורכבים, החדר מדגיש מתקפות סיסמה מציאותיות הנפוצות במהלך מבדקי חדירה פנימיים ומבצעי Red-Team.

לאורך המבדק, אנו משתמשים במספר כלי התקפה כגון Hydra, CeWL, CUPP, Crunch ו-Hashcat כדי לאתר חולשות במדיניות ההזדהות של מרקו ולהשיג גישה לשירותים רגישים יותר ויותר.

מטרות (Objectives)
ניצול פרטי הזדהות חלשים וברירת מחדל במספר שירותים.

יצירת מילוני סיסמאות מותאמים אישית בעזרת OSINT ומילות מפתח של החברה.

ביצוע מתקפות כוח גס (Brute-force) מול פורטלי התחברות בווב ושירותי SSH.

ניתוח תבניות צפויות ליצירת סיסמאות.

מהלך העבודה (Walkthrough)
כדי להתחיל באתגר, הפעלתי תחילה את מופע מכונת היעד מלוח הבקרה של חדר ה-TryHackMe. לאחר מספר רגעים, הפלטפורמה הקצתה כתובת IP ייעודית שמארחת את כל השירותים הפגיעים בחדר.

שלב 2: ניתוח בקשת ההתחברות (Reconnaissance בדפדפן)
כדי לבצע התקפת כוח גס אוטומטית באמצעות כלי כמו Hydra, אי אפשר סתם "לזרוק" סיסמאות לאתר; צריך להבין בדיוק איך טופס ההתחברות מעביר את הנתונים לשרת:

פתיחת כלי המפתחים: לחיצה על F12 (או קליק ימני ובחירה ב-Inspect) ומעבר ללשונית Network.

ניסיון התחברות יזום שנכשל: הקלדת שם משתמש שרירותי (כמו admin) וסיסמה שגויה כדי לבחון את התנהגות המערכת.

חילוץ 4 נתונים קריטיים מתוך הבקשה שנלכדה:

שיטת הבקשה (Method): POST (הנתונים נשלחים בגוף הבקשה ולא כחלק מה-URL).

נתיב האימות (Login Endpoint): /login (הכתובת המדויקת בשרת שמקבלת ובודקת את הטופס).

שמות השדות (Parameters): username ו-password (אלה המשתנים שהשרת מצפה לקבל).

הודעת הכישלון (Failure Message): Invalid credentials. (המחרוזת המדויקת שמופיעה באתר כשההתחברות נכשלת).

<img width="1908" height="873" alt="image" src="https://github.com/user-attachments/assets/fdc39d4b-a240-440b-9ac7-075d659daee4" />


התמונה מציגה בדיוק את תהליך הניתוח הידני (Inspection) של טופס ההתחברות באמצעות כלי המפתחים (Developer Tools) בדפדפן, כדי לחלץ את הנתונים הדרושים עבור כלי הפריצה (Hydra).

הנה הסבר מפורט על מה שרואים בחלק העליון והתחתון של המסך:

---

### 1. החלק העליון (טופס ההתחברות בדפדפן)

* **כתובת ה-URL:** רואים את הכתובת `[http://10.113.171.160:5001/login](http://10.113.171.160:5001/login)`. זה מגדיר את כתובת ה-IP של היעד, את הפורט (`5001`), ואת הנתיב (`/login`).


* **הודעת השגיאה (בתיבה האדומה):** מופיע הטקסט **`Invalid credentials.`**. זהו **תנאי הכישלון (Failure Condition)**. נתון זה נמסר ל-Hydra כדי שתדע שכל עוד התשובה מהשרת מכילה את הטקסט הזה, הסיסמה שנבדקה שגויה.


* **שדות הטופס:** שדה ה-`Username` שבו הוזן `admin`, ושדה ה-`Password` שבו הוקלדה סיסמה שגויה כדי לעורר את השגיאה.



---

### 2. החלק התחתון (לשונית Network בכלי המפתחים)

בלשונית זו מוצגות כל הבקשות שנשלחו בין הדפדפן לשרת ברגע לחיצה על כפתור ההתחברות:

* **השורה הראשונה (הבקשה המרכזית):**
* **Status `200`:** השרת קיבל את הבקשה והחזיר תשובה תקינה (קוד 200 ב-HTTP).


* **Method `POST`:** הבקשה נשלחה בשיטת POST (שיטה שבה נתוני שם המשתמש והסיסמה מועברים בגוף הבקשה ולא כחלק מהקישור).


* **File `login`:** נקודת הקצה (Endpoint) שאליה נשלחה בקשת האימות.




* **השורות הנוספות (304, 404):** טעינת קובצי עיצוב וסקריפטים של האתר (`bootstrap.min.css`, `bootstrap.bundle.min.js`, `favicon.ico`) שנטענו מהזיכרון המטמון (Cache), ואינם רלוונטיים לחקירת תהליך האימות.



---

### מה לוקחים מכאן לפקודת ה-Hydra?

1. **נתיב (Path):** `/login`

2. **שיטה:** `POST` (לכן משתמשים במודול `http-post-form`)


3. **מחרוזת כישלון:** `Invalid credentials.`

4. **פורט:** `5001`

### תרגום שלב 3 (Level 3)

כדי להפעיל את הכלי **CUPP** במצב אינטראקטיבי (שאלות ותשובות), עלינו להשתמש בדגל `-i`:

```bash
python3 cupp.py -i

```

נזין את הפרטים הבאים כדי לייצר את מילון הסיסמאות המותאם אישית שלנו:

* **First Name (שם פרטי):** Marco
* **Surname (שם משפחה):** Bianchi
* **Nickname (כינוי):** marky
* **Birthdate (תאריך לידה בפורמט DDMMYYYY):** 14021995

בשאר שדות הקלט (כמו שם בן/בת זוג, ילדים, חיות מחמד או שמות חברות), פשוט דילגתי (על ידי לחיצה על Enter), והשתמשתי בהתאמות/שאלות ההרחבה שמציע הכלי.

---

לאחר יצירת קובץ המילון (שנשמר כ-`marco.txt`), פתחתי במתקפת Hydra נוספת המכוונת למשתמש **marco** באפליקציית **social.thm**:

```bash
hydra -l marco \
  -P /Downloads/cupp/marco.txt \
  -f -V -t4 \
  -s 5003 \
  social.thm http-post-form \
  "/login:username=^USER^&password=^PASS^:Invalid credentials."

```

#### ניתוח מרכיבי הפקודה:

* **`-l marco`**: בדיקת שם המשתמש מרקו.
* **`-P /Downloads/cupp/marco.txt`**: נתיב לקובץ המילון המותאם אישית שנוצר באמצעות CUPP על בסיס המידע שנאסף עליו.
* **`-f`**: עצירה מידית ברגע שהסיסמה התקינה הראשונה מתגלה.
* **`-V`**: פירוט והצגה על המסך של כל ניסיון הרצה בזמן אמת.
* **`-t4`**: הפעלת 4 תהליכים מקבילים לשמירה על יציבות החיבור.
* **`-s 5003`**: הפורט הייעודי שעליו רצה הרשת החברתית (`social.thm`).
* **`social.thm http-post-form`**: שליחת בקשות מסוג HTTP POST לכתובת היעד שמוגדרת בקובץ ה-hosts.
* **`"/login:username=^USER^&password=^PASS^:Invalid credentials."`**:
* הנתיב: `/login`.
* גוף הבקשה: החלפת משתנה המשתמש `^USER^` והסיסמה `^PASS^`.
* תנאי השגיאה: המחרוזת `Invalid credentials.` שמסמנת שהניסיון נכשל.
